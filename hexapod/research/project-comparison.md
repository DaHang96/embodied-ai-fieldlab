# Hexapod Open-Source Project Comparison

> Day 2 建立。这里记录六足机器人开源项目的研究证据、比较过程和路线决策。三个初始候选先完成比较，NodeHexa 是研究过程中后来发现并经套件审计后选定的实体复现基线；购买不等于已经完成复现。

## 当前筛选约束

- 总预算上限：1500 元；如证据显示值得，可单独追加预算；
- 3D 打印：无个人打印机，接受寻找打印服务；
- 控制平台：接受 Arduino、ESP32 或树莓派；
- 第一个里程碑：一周内看到第一次行走；
- 落地顺序：先复现基础版本，再制作蜘蛛感原创外壳；
- 目标规模：适合个人桌面实验，优先低成本、资料完整、零件可采购的项目；
- 研究边界：项目可作为具身机器人移动能力和角色传播的起点，但不自动等于最终 AI Assistant 任务。

## 来源证据摘要（2026-08-31）

### A：hexapod-ium

- 仓库明确列出 12 个 MG90S/SG90 舵机、Arduino Uno、PCA9685 和 3D 打印部件。
- README 说明电机板需要 5V 供电，所有舵机同时动作时至少需要 2A 上限；这意味着不能只按控制板供电方案采购。
- 软件是基础 Arduino 控制，适合先验证站立、单腿动作和简单步态，但后续 Camera/ROS/AI 接入需要自行扩展。

### B：rookidroid/hexapod

- v2 仓库明确给出 18 DOF、ESP32/Pico、18650 电池和完整 3D 打印清单；其 README 的参考舵机是 DS Power 或 Miuzei 21G class。MG92B 属于 mochi 分支/另一条路线，不能回填为 v2 的原作者舵机。
- README 给出 Arduino IDE 安装、ESP32 库、Wi‑Fi 远程控制、网页标定和 OTA 路径，并估计完整制作通常需要 8–12 小时；该时间不等于打印服务和物流时间。
- 对 Peter Studio 的角色传播更有利，但 18 个舵机、打印件和校准会让 1500 元预算变得敏感。

### C：ggldnl/Hexapod

- 仓库提供 3D 打印件、完整 BOM、Servo2040 固件、树莓派端 Python 控制器、校准工具、ROS2 节点和仿真项目。
- 它最适合作为后续“移动机器人 + 感知/控制/仿真/ROS2”研究架构参考；当前不应把它当成一周内首次行走的默认路线。

### D：NodeHexa（后来发现并选定）

- 这是在完成 A/B/C 初筛之后，通过用户提供的开源仓库、官方器材说明和官方淘宝套件进一步研究的路线，不是最初三项目比较时预先锁定的答案。
- 官方套件把控制板、舵机驱动板、舵机、打印件、电池和充电器组合在一个采购路径中，降低了第一次自行匹配零件的风险。
- 当前选择的是 `套餐B：全套散件（无机盖）·部分组装`、`2000mAh 2S`、含充电器，商品 SKU `5971637489629`，页面审计价格约 ¥634。
- 选择 NodeHexa 的原因不是它在所有维度都最强，而是它在“公开资料、套件完整度、首台实体机器人可复现性、预算和内容连续性”之间更适合当前阶段。
- 当前只确认“已购买、等待到货”，尚未确认实物清单、实际供电、装配质量、上电行为或第一次运动。

## 路线决策时间线

1. **初始比较**：先比较 `hexapod-ium`、`rookidroid/hexapod` 和 `ggldnl/Hexapod`，分别代表低成本快速复现、18 DOF/角色传播和软件/ROS2 架构参考。

4. **当前决策**：购买 NodeHexa V1 作为第一台实体复现基线；A/B/C 继续保留为比较、架构参考和后续内容素材。

## 我们要做的语音助手架构

如果目标是“我说一句话，六足机器人听懂并行动”，需要在开源运动底座上增加一层：

```text
Microphone
  → ASR / Speech-to-Text
  → 意图解析（先用固定指令，后接 LLM）
  → 安全检查与动作白名单
  → 六足机器人的运动 API / ROS2 / Wi‑Fi 控制
  → 行走、转向或停止
  → Speaker / Screen 反馈执行结果
```

需要区分三个逐步升级的目标：

1. **语音遥控**：听到“前进、后退、左转、停止”，映射到固定动作；这不是完整 AI，但最适合早期验证。
2. **语音助手**：听懂“去桌子旁边”“转过来面对我”等更自然的表达，并反馈“正在执行/无法执行”；需要意图解析、状态管理和安全边界。
3. **具身 AI 助手**：结合 Camera、上下文、环境状态和任务规划，自主决定如何行动；这是更长期的研究目标。

因此，六足项目的选择不只看“能不能走”，还要看它是否提供稳定、可调用的运动 API。A 适合低成本先验证语音遥控；B 适合 Wi‑Fi 角色原型；C 最适合后续把语音、Camera、LLM/VLM 接入 Python/ROS2，但不符合当前一周落地的首要约束。

## 已确认的能力里程碑

- **首周里程碑**：完成基础组装、校准、站立和第一次行走；
- **可选交互实验**：如果任务研究证明有价值，再使用电脑或机器人麦克风识别固定语音指令，例如“前进、后退、左转、停止”，并通过安全动作白名单执行；
- **可选表达层**：根据任务方向增加 Speaker 或 Screen，对“正在执行、已停止、无法执行”等状态做反馈；
- **长期探索**：再根据实验结果接入 Camera、上下文和 LLM/VLM，判断是否值得形成具身 AI 助手体验；
- **选择原则**：不要求开源底座自带语音功能，但必须有稳定、可调用、可加安全限制的运动控制接口。

## 控制板与语音/LLM 扩展核验

### 关键结论

六足控制板不需要、也不适合在本地运行完整 LLM。更合理的分工是：

```text
RTX 3060 Laptop / Remote GPU
  负责 ASR、LLM/VLM、任务状态和语音/TTS
          ↓ Wi‑Fi / USB / Serial
ESP32 / Pico W
  负责接收经过安全检查的动作指令、步态控制和停止
          ↓
PCA9685 / Servo Driver → 舵机
```

### A 路线的板子选择

`hexapod-ium` 的 README 同时提到 Arduino Uno 和 ESP32，但如果项目后期一定要接入语音和 LLM，**不建议把 Arduino Uno 作为最终控制板**。官方 Arduino Uno R3 规格是 ATmega328P、32 KB Flash、2 KB SRAM，并且没有板载 Wi‑Fi 或 Bluetooth；它可以负责基础舵机控制，却更适合通过 USB 接收简单动作命令，而不是承担联网和音频/AI 网关。

因此 A 路线应核验并优先采购：

- ESP32 开发板，而不是 Arduino Uno；
- ESP32 通过 Wi‑Fi 接收电脑发送的固定动作指令；
- 麦克风、ASR、LLM 和 Speaker 先放在电脑/远程设备；
- Arduino Uno 仅保留为最低成本的纯运动实验备选。

### B 路线的板子选择

`rookidroid/hexapod` 支持 ESP32 或 Raspberry Pi Pico。Pico W 具备 Wi‑Fi/Bluetooth 和丰富 GPIO，理论上可以作为联网动作控制器；但普通 Pico/Pico H 没有无线能力，不能直接承担无线语音链路。Raspberry Pi 官方资料确认 Pico W 集成 2.4 GHz Wi‑Fi 和 Bluetooth。

因此 B 路线应优先核验：

- 选择 ESP32 版本，或至少选择 Pico W/WH，而不是无无线版本；
- 先通过 Wi‑Fi 接收电脑的动作指令；
- 不把 Pico W 或普通 ESP32 当成 LLM 主机；
- 如果未来要把数字麦克风直接装在机器人上，再单独验证音频输入和固件兼容性。

ESP32-S3 官方支持 I2S 音频输入/输出，因此它可以作为未来“机器人本地麦克风/扬声器”实验的候选，但不能直接假定当前六足仓库的 ESP32 固件无需修改就兼容 ESP32-S3。

### 当前控制板决策

| 路线  | 当前建议                              | 语音/LLM 扩展判断                             |
| --- | --------------------------------- | --------------------------------------- |
| A   | ESP32 优先；Arduino Uno 只做最低成本基础运动验证 | 适合“电脑语音 → Wi‑Fi/串口 → 固定动作”，后续需自己补充通信协议  |
| B   | ESP32 优先；Pico 只考虑 Pico W/WH       | 现成 Wi‑Fi 遥控路径更适合做第一版语音遥控和角色原型           |

## 电池供电架构调研（2026-09-01）

用户希望尽量一步到位做成可脱离电源线的六足机器人，因此补充比较已落地项目和在售成品的供电方式。

| 案例                   | 电池方案                     | 电源管理方式                                        | 对本项目的启示                                                |
| -------------------- | ------------------------ | --------------------------------------------- | ------------------------------------------------------ |
| `rookidroid/hexapod` | 2 × 18650 + 电池盒          | 仓库 BOM 列出电池和开关，但公开说明没有把降压/保险保护讲清楚             | 可以作为机械和 ESP32 路线参考，但不能直接照抄“2 节电池接舵机”                   |
| `runeharlyk/Hexapod` | 2S2P 18650（4 节）          | 7 个 Buck 转换器                                  | 证明多舵机机器人需要认真做电源分配；复杂度和成本不适合首版                          |
| `ggldnl/Hexapod`     | 7.4 V 2S LiPo            | 2 个 8 A UBEC：一路 5 V 给树莓派/Servo2040，一路 6 V 给舵机 | 是目前最清晰的“电池→分路稳压→控制/舵机”参考，但整机约 280 欧元，超出当前预算            |
| DFRobot ROB0080      | 7.4 V 电池                 | 官方说明称一块 7.4 V 电池同时供 Arduino Mega 和两个舵机驱动板     | 说明成品会把稳压/驱动集成到系统中；项目已停产，只作历史参考                         |
| Waveshare HexArth    | 6 × 18650，总容量标称 4000 mAh | 内置电池保护和 DC 5.5×2.1 mm 充电接口                    | 成品方向：电池、保护、充电和控制板一体化；但使用 12 V 总线舵机，不适合直接复用 MG90S       |
| Hiwonder miniHexa    | 2 × 3.7 V 18650，2200 mAh | 机身 DC 接口充电，使用 8.4 V 充电器；ESP32 控制              | 与本项目定位最接近：小型、ESP32、18 舵机、电池、可扩展视觉/语音；适合作为产品级参考，不代表必须购买 |

关键结论：

1. 成品和成熟项目都采用电池驱动，不需要运行时连接电源线；
2. 电池通常是 2S（标称 7.4 V）或 3S（标称 11.1 V），但舵机和控制板不会直接承受这个电压；
3. 需要通过 UBEC/Buck 将电池电压变成舵机所需电压，并为 ESP32/上位机提供稳定的逻辑电源；
4. 充电一般使用匹配电池串数的专用充电器，例如 2S 锂电池使用 8.4 V 充电器，不能把普通 USB-C 线直接当作充电器；
5. 因此“改用电池”不是取消 5 V 电源，而是把 5 V 稳压模块放进机器人内部。这个模块比 5 V 5 A 桌面适配器更容易按 `5V 5A/8A UBEC` 或 `DC-DC降压模块` 搜索。

上述判断参考：[rookidroid/hexapod](https://github.com/rookidroid/hexapod)、[runeharlyk/Hexapod](https://github.com/runeharlyk/Hexapod)、[ggldnl/Hexapod-Hardware](https://github.com/ggldnl/Hexapod-Hardware)、[DFRobot ROB0080](https://wiki.dfrobot.com/rob0080/)、[Waveshare HexArth](https://docs.waveshare.com/HexArth)、[Hiwonder miniHexa](https://docs.hiwonder.com/projects/miniHexa/en/v1.2/docs/1_Read_First.html)。

### 当前供电决策调整

本项目改为“电池优先的最终架构，低风险台架验证仍然保留”。首选候选组合为：

```text
2S 7.4 V 受保护电池包
        ↓
5 V 5 A/8 A UBEC 或高电流 Buck
        ├─ PCA9685 V+ → 舵机
        └─ 独立稳定 5 V → ESP32-S3 逻辑电源
```

当前不直接锁定某个电池型号，原因是需要先确认所选 Replica 21g-class servo 或未来 Engineering servo 的实际工作电压、堵转电流、连接器和机器人总重量。第一版优先研究 2S 18650 保护电池包；高倍率 2S LiPo 作为性能备选，但需要额外的平衡充电器和更严格的安全管理。

### 淘宝候选核验（2026-09-01）

#### 用户提供的电池链接

页面标题为“18650 大容量锂电池 2S 7.4 V / 3S 11.1 V”，可选 `2S7.4V-5000mAh`、`7500mAh`、`10000mAh` 等组合，部分 SKU 标注 `T母 + XH2.54-3P 平衡充`，页面价格约 48 元起。

#### 用户提供的 UBEC 链接

页面标题为“UBEC 模型稳压降压模块 4 A/6 A/8 A，输出 5 V/6 V/7.4 V，锂电 4–6S”，用户看到的 8 A 价格约 38 元。页面当前参数显示电压规格为 6 V，SKU 还需要单独选择电流和输出电压。

当前判断：**不建议用于计划中的 2S 电池**。`4–6S` 通常意味着输入从 4S（约 14.8 V 标称）开始，不能根据“8 A”三个字推断它支持 2S。除非卖家书面确认“2S 输入可用 + 选择 5 V/8 A 输出”，否则不采购。

#### 连接器解释与当前建议

- `T母`：电池主电源输出插头，通常需要与 UBEC 输入端的 `T公` 配对；
- `XH2.54-3P`：2S 电池平衡充接口，用于逐节平衡充电；
- `DC5.5`：圆孔电源插头，方便但不建议作为多舵机大电流主电源的默认连接器；
- `XT30/XT60`：航模常见大电流主电源连接器，适合后期重新设计供电线束。

第一版若使用 2S 电池，优先采用“带 BMS 的 2S 电池包 + 明确支持 2S 的 5 V 8 A UBEC + 匹配的 8.4 V 充电器”。如果电池没有 BMS，而只有 XH2.54 平衡口，就必须使用真正的 2S 平衡充电器，不能把普通 8.4 V/2 A 适配器直接当作安全充电器。

## 当前商品页核验：ESP32-S3-DEV-KIT-NXRX

用户提供的天猫商品页显示，该系列采用 ESP32-S3-WROOM，支持 ESP-IDF、Arduino 和 MicroPython，提供 2.4 GHz Wi‑Fi、Bluetooth LE、Type‑C，以及 CH343/CH334 USB/UART 芯片；图文详情还标注其排针布局兼容 ESP32-S3-DevKitC-1。微雪官方中文说明进一步确认了模组、Flash/PSRAM、引脚电平和 SKU 对应关系。

截图复核后确认：商品图文详情明确展示了 8 MB/16 MB PSRAM、8 MB/16 MB/32 MB Flash 的版本组合；`M` 是加焊排针，`U` 是外置天线版本。页面对 `ESP32-S3-DEV-KIT-N16R8-M` 标注了“推荐”。开发板本身没有板载麦克风或扬声器，后续语音能力需要通过电脑音频设备，或额外连接 I2S 麦克风/音频输出模块实现。

| 商品后缀        | 含义                                                 | 对本项目的影响                     |
| ----------- | -------------------------------------------------- | --------------------------- |
| `N8R8`      | 8 MB Flash + 8 MB PSRAM；未预焊排针                      | 能做六足控制和联网，需自己焊排针            |
| `N8R8-M`    | 与 N8R8 相同；已预焊排针                                    | 省焊接时间，内存余量较小但够早期控制          |
| `N16R8`     | 16 MB Flash + 8 MB PSRAM；未预焊排针                     | 为音频缓存、OTA 和扩展库留出更多余量        |
| `N16R8-M`   | 与 N16R8 相同；已预焊排针                                   | **当前推荐**：扩展余量和易用性平衡最好       |
| `N16R8-U`   | 16 MB Flash + 8 MB PSRAM；外置天线接口；未预焊排针              | 只有在机器人外壳遮挡天线或需要把天线移出外壳时才考虑  |
| `N16R8-UM`  | N16R8-U + 已预焊排针                                    | 当前不需要，外置天线会增加机械布置复杂度        |
| `N32R16V`   | 32 MB Flash + 16 MB PSRAM；未预焊排针；WROOM-2/1.8 V 相关设计 | 对当前六足控制过剩，且增加固件/电气核验复杂度     |
| `N32R16V-M` | N32R16V + 已预焊排针                                    | 当前不推荐，除非以后明确要做本地大型音频/视觉缓存实验 |

这里的命名规律可以简单理解为：`N` 后面的数字是 Flash 容量，`R` 后面的数字是 PSRAM 容量，`M` 表示预焊排针，`U` 表示外置天线版本；`V` 版本涉及 WROOM-2 和 1.8 V 存储接口，不能只按“内存更大”来选择。版本定义参考[微雪官方对比表](https://docs.waveshare.com/ESP32-S3-DEV-KIT-N8R8)和[官方产品页](https://www.waveshare.com/product/esp32-s3-dev-kit-n8r8.htm)。

### 选择结论

当前推荐购买型号为 **ESP32-S3-DEV-KIT-N16R8-M**，理由是：

- 有 Wi‑Fi/Bluetooth，适合电脑语音服务向六足发送动作指令；
- 16 MB Flash + 8 MB PSRAM，为音频缓冲、OTA、扩展库和后续轻量语音实验留出余量；
- 已预焊排针，减少第一次硬件搭建的不确定性；
- 普通板载天线足够桌面范围使用，不需要先处理外置天线结构；
- 不选择 N32R16V，避免为当前项目引入不必要的 1.8 V/固件兼容风险。

注意：当前 GitHub 六足项目原文通常按“ESP32 Dev Module”说明，尚未证明其固件在 ESP32-S3 上无需修改即可运行。下单前必须先做一次台架验证：Arduino IDE 识别 `ESP32S3 Dev Module` → Wi‑Fi 连接 → PCA9685 I2C 通信 → 单个舵机低速动作。通过后再扩大到 12/18 个舵机。

## 两阶段执行器决策（2026-09-01）

当前只允许验证 `rookidroid/hexapod` v2 的 Replica 执行器，不启动最终 Engineering V2 的 30–40 kgf·cm 级采购：

```text
READY_FOR_REPLICA_SERVO_SEARCH = true
READY_FOR_FINAL_ENGINEERING_SERVO_SEARCH = false
V2_HIGH_TORQUE_SERVO_DROP_IN = UNVERIFIED
```
