> 更新时间：2026-09-04
>
> 本文件记录 Phase 1 对项目叙事、状态和到货前执行顺序的统一结果。它不是新的 Day 计划，也不替代各日后台记录。

## 1. 当前唯一总目标

> 在 60 天内真正做出并运行开源具身机器人，通过六足机器人和机械臂的实际实验，探索它们能做什么，并把过程沉淀为原创内容和作品集。

“桌面 AI 助手”不再是项目总目标。它可以作为未来某个机器人任务或交互体验的候选方向，但必须由 `Robot Task Research`、早期实验和真实结果决定。

## 2. 三条执行线

### Line A — NodeHexa 六足机器人落地

NodeHexa V1 是当前第一台已购买的实体机器人。当前状态是：套餐 B、2000mAh 电池、含充电器、部分组装，等待到货。到货后从清点、装配复核、供电检查、固件/控制链和第一次运动开始。

### Line B — 机械臂具身智能研究

机械臂继续作为并行研究路线，关注开源硬件、遥操作、相机、数据、策略和真实任务。具体硬件与任务不提前锁死，等研究和早期实验提供证据。

### Line C — 内容、Developer Experience 与作品集

PeterStudio、社交媒体、Developer Experience 和 Portfolio 共同记录前两条线的真实过程。内容服务于实验，不反过来制造未经验证的机器人能力。`peterstudio.online` 负责个人 Build Log；SEO 网站只接收经过事实验证的内容机会，不在本项目中执行 SEO 策略。

技术理解、实验记录和职业映射是三条线的支撑机制，不再作为独立的第四条主线。

## 4. NodeHexa 到货后的执行顺序

具体操作采用 Guided Execution Mode，每次只推进一个实际步骤：

1. 到货记录与包装/清单拍摄；
2. 3D 打印件、板卡、舵机、电池、充电器和紧固件清点；
3. 不接电的结构与螺丝复核；
4. 电池、主板、舵机电源和连接器的安全检查；
5. 固件、控制软件和 Wi-Fi/网页控制链准备；
6. 低风险上电与单动作验证；
7. 三条腿/整机装配状态复核；
8. 悬空动作、站立和基础行走测试；
9. 记录失败、抖动、电流、温升和可重复性；
10. 将真实结果分别沉淀到 Robot、DX、Content 和 Portfolio。

如果硬件尚未到货，只做准备、文档审计、环境验证和内容素材准备，不把替代验证写成真实机器人结果。

## 5. Robot Task Research 状态

任务研究保留历史路径 `robot-arm/tasks/`，但统一使用通用的 `Robot Task Research` 叙事。桌面整理、递取物品、内容创作辅助等只是候选方向，不能写成最终任务。

最终任务要在研究和早期实验后决定，并同时考虑可行性、生活意义、可理解性、视觉表现、失败价值、重复性、安全、成本和升级空间。

- D 盘主项目是唯一继续编辑的工作区；
- Codex worktree 暂停编辑并保留原状；
